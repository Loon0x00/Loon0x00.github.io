Single-Node Configuration

Single nodes are defined in the [Proxy] section of the main configuration, one node per line:

[Proxy]
Node name = protocol,server,port,required protocol arguments,optional arguments

Arguments are separated by ASCII commas. Enclose a password, path, or argument value in double quotes if it contains an ASCII comma.

note

Loon does not provide proxy nodes. Server addresses, ports, passwords, keys, and other connection details must be provided by your service provider.

Common Arguments​

The following arguments are available to node protocols that support them. Each protocol's full example includes its applicable arguments.

ArgumentDescription
server-dnsDNS servers used to resolve the node server's domain name. Separate multiple servers with ASCII commas and enclose the entire value in double quotes. Requires Loon 3.5.2 (Build 996) or later
ip-modeIP stack policy used when resolving the node server's domain name: v4-only, dual, prefer-v4, prefer-v6, or v6-only
fast-openWhether to enable TCP Fast Open
udpWhether the node can forward UDP
block-quicWhether to block QUIC; set this to false when the node needs to forward QUIC
skip-cert-verifyWhether to skip TLS certificate verification
sniServer name used in the TLS handshake
tls-profileTLS ClientHello fingerprint: global, default, safari-ios18, safari-ios-26, chrome, or chrome147
tls-cert-sha256SHA-256 fingerprint of the server certificate
tls-pubkey-sha256SHA-256 fingerprint of the server certificate's public key; takes priority when both fingerprint types are configured

Node DNS​

server-dns requires Loon 3.5.2 (Build 996) or later.

server-dns is used only to resolve the node server's domain name. It does not replace the global DNS used for ordinary domain requests. The following server formats are supported:

  • Plain DNS (DoU): system, 223.5.5.5, 223.5.5.5:53, 2001:4860:4860::8888, or [2001:4860:4860::8888]:53
  • DNS over HTTPS (DoH): https://dns.example.com/dns-query
  • DNS over QUIC (DoQ): quic://dns.example.com
  • DNS over HTTP/3 (DoH3): h3://dns.example.com/dns-query

When multiple servers are configured, Loon queries them concurrently and uses the first valid result returned:

server-dns="223.5.5.5,https://dns.example.com/dns-query,quic://dns.example.com,h3://dns.example.com/dns-query"

Double quotes are recommended even when only one server is configured. An unquoted single-server value can still be parsed; Loon adds double quotes when saving the configuration.

The resolution order for a node server domain is: matching Host Map, the node's server-dns, SSID DNS, and global DNS. After the node's server-dns is selected, a failed query does not fall back to SSID DNS or global DNS. Subsequent CNAME lookups continue to use the same node DNS servers.

VLESS Encryption​

VLESS Encryption applies to VLESS over TCP, WebSocket, HTTP obfuscation, and XHTTP. It can run on its own or inside standard TLS or REALITY. The server must also enable VLESS Encryption. Use the mode and public keys supplied by the server.

ArgumentDefaultDescription
encryption-modenonenone disables Encryption. native uses the base encryption mode. xorpub also masks public-key material in the handshake. random additionally masks the encrypted record length field. The node editor selects native when you enable Encryption
encryption-rtt0rtt0rtt resumes a session when a valid ticket is available. The first connection and connections with expired tickets perform a full handshake. 1rtt performs a full handshake for every new Encryption session
encryption-public-keysUnsetRequired when Encryption is enabled. Enter server-provided Base64URL public keys. Supports X25519 and ML-KEM-768 keys. Separate multiple keys with periods (.) and preserve the server-provided order. The REALITY public key goes in public-key
encryption-padding100-111-1111.75-0-111.50-0-3333Custom padding for a full handshake. Separate probability-minimum-maximum triplets with periods. Starting with the first triplet, alternate padding lengths in bytes and gaps between segments in milliseconds. Set the first probability to 100 and both lengths to at least 35. For example, 100-128-128 adds 128 bytes with no gap. Omit this argument to keep the default

XTLS Vision​

Set flow to xtls-rprx-vision or xtls-rprx-vision-udp443. Omit flow to leave Vision off.

XHTTP​

XHTTP is a transport for VLESS, VMess, and Trojan over HTTP/1.1, HTTP/2, or HTTP/3. It forwards TCP and can carry application UDP datagrams in XHTTP requests when udp=true. VMess uses AEAD with alterId=0. Trojan uses standard TLS or REALITY. For VLESS over XHTTP, enable VLESS Encryption to use XTLS Vision.

[Proxy]
VLESS-XHTTP = VLESS,vless.example.com,443,"52396e06-041a-4cc2-be5c-8525eb457809",transport=xhttp,path=/xhttp,host=vless.example.com,over-tls=true,sni=vless.example.com,alpn=h2,xhttp-mode=packet-up,udp=true
VMess-XHTTP = VMess,vmess.example.com,443,aes-128-gcm,"52396e06-041a-4cc2-be5c-8525eb457809",alterId=0,transport=xhttp,path=/xhttp,host=vmess.example.com,over-tls=true,sni=vmess.example.com,alpn=http/1.1,xhttp-mode=stream-up,udp=true
Trojan-XHTTP = Trojan,trojan.example.com,443,"password",transport=xhttp,path=/xhttp,host=trojan.example.com,sni=trojan.example.com,alpn=h2,xhttp-mode=stream-one,udp=true

Transport Modes​

HTTP/1.1, HTTP/2, and HTTP/3 all support the three explicit modes. Match the server configuration.

ModeUplink and downlink organization
packet-upThe downlink uses a persistent GET. Uplink data is split into multiple sequenced HTTP requests
stream-upThe downlink uses a persistent GET and the uplink uses one persistent request. Both requests use the same session ID
stream-oneThe request body and response body of one persistent request carry the uplink and downlink, respectively
autoSelects packet-up for standard TLS or plaintext. With REALITY, selects stream-one without a separate downlink and stream-up with one

Advanced Arguments​

Write arguments as key=value. Their scope follows the mode the node actually uses. Arguments that accept a range also accept a single value or a closed range such as 100-300. Main request headers apply to the main endpoint. A separate downlink GET uses its own request headers.

XMUX​

Direct XHTTP nodes use XMUX by default. With HTTP/2 and HTTP/3, multiple XHTTP sessions can share existing connections. HTTP/1.1 reuses connections for short packet-up uploads. Persistent requests use their own connections.

These arguments apply to the main endpoint. The same endpoint also handles downloads when no separate downlink is configured. Limits accept a positive integer or a closed range. When all arguments are omitted or set to 0, the defaults are 3 pool entries, 600-900 requests per entry, and a reuse lifetime of 1800-3000 seconds. When any argument is nonzero, the configured limits apply as a group and omitted limits are treated as 0. Only one of max-concurrency and max-connections may be positive.

ArgumentDescription
xhttp-xmux-max-concurrencyMaximum number of XHTTP sessions assigned concurrently to one pool entry. Loon can open a new entry when this limit is reached. 0 leaves this concurrency limit unset
xhttp-xmux-max-connectionsNumber of reusable entries to maintain in the pool. With 1, new sessions prefer the same entry while it has capacity. 0 leaves the pool size unspecified
xhttp-xmux-max-reuse-timesTotal number of session assignments per entry, including the first. 1 assigns the entry to one session. 0 leaves this count unlimited
xhttp-xmux-http-max-requestsTotal HTTP requests per entry. 0 leaves the count unlimited. H2/H3 stream-up needs capacity for two requests when both directions use the same endpoint
xhttp-xmux-http-max-reusable-secsHow many seconds after creation an entry can accept new requests or sessions. 0 leaves this time limit unset
xhttp-xmux-http-keepalive-secsH2 PING or H3 QUIC keepalive interval in seconds. Omitted or 0 uses 45 seconds for H2 and 10 for H3. -1 disables keepalive

Separate Downlink · Endpoint and Request​

With stream-up or packet-up, the persistent download GET can use a separate address, port, and HTTP version. auto selects a split mode according to the transport mode rules. The upload and download use the same XHTTP session ID. Both endpoints must recognize that session. Each direction can select its own HTTP version within the limits of its security layer.

ArgumentDescription
xhttp-download-serverDownlink server hostname or IP address. Required for a separate downlink
xhttp-download-portDownlink port, 1–65535. Required for a separate downlink
xhttp-download-hostHost or :authority for the GET. When omitted, a secured connection uses the downlink SNI if set and otherwise uses the server address
xhttp-download-pathBase path for the GET. Defaults to / and may include query arguments. Use the downlink server's actual path
xhttp-download-headerAdds one header only to the separate downlink GET. Repeat xhttp-download-header="Name: Value" for different names. Set Host with xhttp-download-host
xhttp-download-alpnA single HTTP version for the downlink. Plaintext uses http/1.1. Standard TLS supports http/1.1, h2, and h3. REALITY uses h2. The default is h2 for a secured connection and http/1.1 for plaintext

Separate Downlink · Security​

ArgumentDescription
xhttp-download-over-tlstrue enables standard TLS. The default is plaintext. When a downlink REALITY public key is set, omitting this argument enables the security layer. An explicit false is incompatible with REALITY

This example uses H3 with TLS for upload and H2 with TLS for download. Use the server-provided downlink address, port, and path.

VLESS-XHTTP-Split = VLESS,upload.example.com,443,"52396e06-041a-4cc2-be5c-8525eb457809",transport=xhttp,over-tls=true,sni=upload.example.com,alpn=h3,path=/xhttp,xhttp-mode=stream-up,xhttp-download-server=download.example.com,xhttp-download-port=443,xhttp-download-sni=download.example.com,xhttp-download-over-tls=true,xhttp-download-alpn=h2,xhttp-download-path=/xhttp

Separate Downlink · XMUX​

These arguments apply only to separate downlink H2 and H3 connections. Each separate HTTP/1.1 download GET uses its own TCP connection. Omit the whole group to inherit the main XMUX settings. Setting any argument configures the entire downlink group independently. Group defaults, range syntax, and mutually exclusive limits follow the XMUX rules.

xhttp-download-xmux-http-max-reusable-secsReuse lifetime per downlink entry in seconds
xhttp-download-xmux-http-keepalive-secsDownlink keepalive interval in seconds. 0 uses the default for the selected HTTP version. -1 disables keepalive

WireGuard​

A WireGuard node consists of interface arguments and one or more peers:

WireGuard = WireGuard,interface-ip=192.168.2.2,interface-ipv6=2001:db8:1::2,private-key="qF22B3ezOhWGJA4SHwQSsgMa9d6mPGHyFdZMaDTae2E=",mtu=1280,dns=192.168.2.1,dnsv6=2001:db8:1::1,keepalive=45,peers=[{public-key="JFuTIJEcFnt8R04UnAE5o2WfIPJUsumSxsD2ayXzoWY=",preshared-key="yVNv5K05AwVnWaR4OB8BlMX3jJlkS74aKlYC3PD95IE=",reserved=[1,2,3],allowed-ips="0.0.0.0/0,::/0",endpoint=wg.example.com:51820}],udp=true,server-dns="223.5.5.5,https://dns.example.com/dns-query"
ArgumentDescription
interface-ipWireGuard interface IPv4 address
interface-ipv6WireGuard interface IPv6 address
private-keyLocal private key
mtuInterface MTU; defaults to 1280 when omitted
dnsIPv4 DNS used inside the tunnel
dnsv6IPv6 DNS used inside the tunnel
keepalivePersistent Keepalive interval in seconds; defaults to 45 when omitted

Tailscale​

Supported starting with Loon 3.5.4 (Build 1016).

A Tailscale node joins your Tailscale network (tailnet) and forwards TCP and UDP through devices in that network. Device addresses and peer connection information are provided by the control server, so you do not need to configure a server address, port, or WireGuard peer manually.

Format:

Node name = tailscale,optional arguments

Browser authorization example:

Tailscale = tailscale,hostname=loon-iphone

When auth-key is omitted, the node obtains a browser authorization URL the first time it is used. After enabling the VPN, send a request through this node. iOS or macOS displays an authorization notification; tap it to open the browser and sign in. Make sure notifications are enabled for Loon. While the VPN is connected, you can also use the Log In action on the node page. Loon saves the identity after authorization and reuses it for subsequent connections.

Using an Auth Key and specifying an exit node:

Tailscale-Exit = tailscale,auth-key="tskey-auth-replace-with-your-key",hostname=loon-iphone,exit-node=100.101.102.103

Set exit-node to auto to randomly select from the available exit nodes. When device information is refreshed, Loon keeps the current selection as long as it remains available.

Example that allows tailnet devices to access local services and advertises this device as an exit node:

Tailscale-Home = tailscale,hostname=loon-home,allow-inbound=true,advertise-exit-node=true,exit-fake-ip=true

When allow-inbound or advertise-exit-node is enabled, Loon proactively connects this node after the VPN starts and keeps it online. Advertising an exit node requires approval in the control panel. Enable only allow-inbound if you only want other devices to access local services.

Full argument example:

Tailscale = tailscale,control-url="https://controlplane.tailscale.com",auth-key="tskey-auth-replace-with-your-key",hostname=loon-iphone,exit-node=auto,accept-routes=true,accept-dns=true,magic-dns=true,allow-inbound=false,advertise-exit-node=false,exit-fake-ip=true,path-mode=auto,mtu=1280,idle-session-timeout=300,ip-mode=prefer-v4,server-dns="223.5.5.5,https://dns.example.com/dns-query",udp=true,block-quic=true
ArgumentDefaultDescription
auth-keyOmittedAuth Key used to register the device. A valid key normally avoids browser sign-in; omit this argument to use browser authorization. Enter the key itself here, not a browser authorization URL
control-urlhttps://controlplane.tailscale.comControl server URL. This argument can be omitted; specify the corresponding HTTP or HTTPS URL when using a custom control server
hostnameAutomatically generatedDevice name used after this device joins the Tailscale network; this is distinct from the node name in Loon
exit-nodenoneDevice used as the Internet exit. none disables exit-node routing; auto selects one automatically. You can also specify a device name, full MagicDNS name, or Tailscale IP address
accept-routestrueUse subnet routes advertised by devices. This allows access to other devices on their local networks, such as reaching a NAS through a Mac at home
accept-dnstrueAccept DNS servers, split-DNS rules, and search domains provided by Tailscale. When using an exit node, Loon selects DNS according to the provided settings or sends queries through the exit node. When disabled, ordinary public domains use Loon's existing DNS flow, while device MagicDNS names can still be resolved from downloaded device information
magic-dnstrueAutomatically add routing rules for full MagicDNS names and device IP addresses from device information. When MagicDNS is enabled for the tailnet, Loon also adds a rule for its domain suffix. Matching requests use this node independently of accept-dns
allow-inboundfalseAllow authorized tailnet devices to connect to local TCP or UDP services, such as SSH or HTTP, through this device's Tailscale address
advertise-exit-nodefalseAdvertise this device as an exit node. After approval in the control panel, other tailnet devices can select it as their exit; this device's Loon rules determine how Internet traffic is forwarded
exit-fake-iptrueWhen this device acts as an exit and handles client DNS queries, return Fake IP addresses for eligible A or AAAA queries. During forwarding, Loon uses the address to recover the domain name and applies local domain rules. Set to false to return real IP addresses
path-modeautoauto selects the path automatically, attempting a direct P2P connection and using a DERP relay when necessary; derp uses DERP relays only
mtu1280MTU of the inner IP packet. Values from 576 through 1280 are allowed; values below 1280 require ip-mode=v4-only
idle-session-timeout300Session idle timeout, in seconds, after all traffic connections have closed. Enter a non-negative integer; 0 disables idle shutdown. The node reconnects the next time it is used, while the saved identity is retained. This value is fixed at 0 when allow-inbound or advertise-exit-node is enabled
ip-modeUnspecifiedAddress-family policy: v4-only, dual, prefer-v4, prefer-v6, or v6-only. This affects the IPv4 or IPv6 addresses used for domain resolution and destination connections
server-dnsNot setDNS used to resolve domain names in control-server, relay-server, and similar connection addresses. See Node DNS for the format. This does not replace DNS settings provided by Tailscale
udptrueWhether to forward application UDP traffic. This is not a P2P switch; set path-mode=derp to use relays only
block-quictrueWhether to block QUIC. Set this to false and keep udp=true when QUIC must be forwarded through the node

accept-dns determines how domain names are resolved, while magic-dns determines which node forwards traffic for device names and IP addresses. For example, automatically routing nas.example.ts.net through this Tailscale node does not mean that all public-domain DNS queries are sent through the node.

Automatic rules are saved after the device first joins the tailnet and refreshed on subsequent connections. Saved rules can also be loaded after the VPN restarts. Automatic magic-dns routing applies in rule mode.

note
  • exit-node identifies the device that receives and forwards traffic; it does not advertise the current Loon device as an exit node. The selected device must have exit-node functionality enabled and be approved for use in the control panel.
  • The default, exit-node=none, provides access to Tailscale devices and accepted subnets. To reach ordinary Internet addresses through this node, specify an available exit node.
  • Loon's rules or global mode still determine whether ordinary requests use this node. accept-routes=true only permits the use of subnet routes; it does not automatically add the entire remote LAN to Loon's routing rules.

Hysteria 2​

Format:

Node name = Hysteria2,server,port,"password",optional arguments

Full argument example:

Hysteria2 = Hysteria2,hy2.example.com,443,"password",sni=hy2.example.com,skip-cert-verify=false,tls-cert-sha256=0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef,tls-pubkey-sha256=abcdef0123456789abcdef0123456789abcdef0123456789abcdef0123456789,alpn="h3",salamander-password=obfs-password,server-ports="20000:20100",hop-interval=30,download-bandwidth=100,fast-open=true,udp=true,block-quic=false,ip-mode=prefer-v4,server-dns="223.5.5.5,quic://dns.example.com"

download-bandwidth is measured in Mbps. server-ports configures port hopping, and hop-interval is the number of seconds between port changes.

Gecko Obfuscation​

Building on Salamander, Gecko splits QUIC handshake datagrams into multiple UDP datagrams with random padding, reducing the fixed-length signature of handshake packets. The node's obfuscation method and password must match the server configuration.

ArgumentDescription
gecko-passwordEnables Gecko and sets its obfuscation password. The password after the port in the node format is used for Hysteria 2 authentication; configure the obfuscation password separately with this argument
gecko-password-base64When the obfuscation password contains double quotes or control characters, specify the standard Base64 encoding of its raw UTF-8 bytes. Use either this argument or gecko-password
salamander-passwordSpecify this when the server uses Salamander. Configure only one obfuscation method per node

Configure a Gecko node in the [Proxy] section:

Hy2-Gecko = Hysteria2,hy2.example.com,443,"auth-password",sni=hy2.example.com,gecko-password="obfs-password",udp=true

You can also import a hysteria2:// or hy2:// URI with obfs=gecko and obfs-password in its query arguments. Percent-encode passwords containing special characters according to URL rules.

hysteria2://auth-password@hy2.example.com:443/?sni=hy2.example.com&obfs=gecko&obfs-password=obfs-password#Hy2-Gecko

Snell​

Supported starting with Loon 3.5.4 (Build 1017).

Supports TCP forwarding and standard UDP forwarding with Snell v4 and v5. Standard UDP datagrams are carried over Snell's TCP connection.

Configuration format

Node name = Snell,server,port,"PSK",version=4,optional arguments

Replace "PSK" with the pre-shared key configured on the server. You can also write psk="PSK" in the same position.

Configuration examples

[Proxy]
Snell-v4 = Snell,snell.example.com,6160,"your-psk",version=4
Snell-v5 = Snell,snell.example.com,6161,"your-psk",version=5,udp=true
Snell-HTTP = Snell,snell.example.com,6162,"your-psk",version=4,obfs=http,obfs-host=www.example.com,obfs-uri=/,udp=true,block-quic=false,ip-mode=prefer-v4,server-dns="223.5.5.5,https://dns.example.com/dns-query"

Configure obfs=http only when the server uses HTTP obfuscation.

ArgumentDescription
versionSupports 4 and 5; defaults to 4
udpSet to true to allow UDP forwarding; defaults to false. The server must also support UDP forwarding
block-quicWhether to block QUIC traffic; defaults to true. Set to false to allow eligible QUIC traffic through standard UDP forwarding
obfsObfuscation type: none or http; defaults to none. The argument name obfs-name is also supported
obfs-hostHost used for HTTP obfuscation. Applies only with obfs=http and defaults to the node server address
obfs-uriRequest path used for HTTP obfuscation. Applies only with obfs=http, must begin with /, and defaults to /
ip-mode, server-dnsOptions for resolving the node server's domain name; see Common Arguments

When adding a Snell node manually, Loon uses v4. To specify v5, add version=5 to the node in the [Proxy] section of the configuration file.

Snell v5 QUIC Proxy Mode is not yet supported.

Mieru​

Loon uses Mieru over TCP. Enter the address and port of the Mieru server's TCP listener (mita). When UDP is enabled, the same TCP transport carries UDP datagrams.

Configuration Format

Node name = mieru,server,port,"username","password",optional arguments

Examples

[Proxy]
Mieru-TCP = mieru,mieru.example.com,8443,"alice","your-password"
Mieru-UDP = mieru,mieru.example.com,8443,"alice","your-password",udp=true,block-quic=false,ip-mode=prefer-v4,server-dns="223.5.5.5,https://dns.example.com/dns-query"
Mieru-Pattern = mieru,mieru.example.com,8443,"alice","your-password",udp=true,traffic-pattern=CCoQARoECAEQAyIKCAMqBjBjYjFmZioECAwQGDIECAEQcA==
ArgumentDefaultDescription
ServerRequiredHostname or IP address of the Mieru server. IPv6 addresses can use square brackets, as in [2001:db8::1]
PortRequiredTCP port the server listens on, from 1 to 65535
Username and passwordRequiredEnter the server-provided credentials in this order. Each must be 1–64 bytes in UTF-8. Use double quotes to preserve commas and leading or trailing spaces
udpfalseSet to true to enable UDP over TCP. The connection to the server still uses the same TCP port
block-quictrueBlocks QUIC by default. To forward QUIC, set both udp=true and block-quic=false
traffic-patternUnsetOptional client traffic pattern containing the standard Base64 encoding of a Mieru Protobuf configuration. When omitted, the default traffic pattern is used
ip-modeUnsetAddress-family policy for resolving the node hostname. Accepts auto, v4-only, dual, prefer-v4, prefer-v6, and v6-only
server-dnsUnsetDNS servers for resolving the node hostname. Separate multiple addresses with commas and quote the entire value. See Common Arguments for the supported formats

Omitting udp from a configuration line leaves UDP off. When you add a Mieru node in the iOS or macOS editor, the UDP switch starts on and the editor saves it as udp=true.

Traffic Pattern​

A traffic pattern can adjust Mieru's TCP segmentation, encrypted-frame padding, low-entropy encoding, and related behavior. The client and server can configure their respective sending behavior independently. Use the Base64 value supplied by the node provider, or export the current configuration from the official Mieru client with mieru export traffic-pattern. Preserve the value exactly when copying it, including trailing = padding characters. See the official Mieru traffic-pattern documentation.

When adding or editing a local Mieru node on iOS or macOS, paste the Base64 value under Proxy Options → Traffic Pattern. An existing value is populated when editing; clear it and save to remove the argument. Loon also reads this argument from imported mierus:// URIs and validates the traffic-pattern format when saving.

Custom by JavaScript​

script-path can be a local script filename or a remote URL. Full argument example:

Custom = Custom,custom.example.com,443,aes-128-gcm,"password",script-path=https://example.com/custom-proxy.js,sni=custom.example.com,skip-cert-verify=false,tls-profile=chrome,tls-cert-sha256=0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef,tls-pubkey-sha256=abcdef0123456789abcdef0123456789abcdef0123456789abcdef0123456789,block-quic=false,ip-mode=prefer-v4,server-dns="223.5.5.5,https://dns.example.com/dns-query"

Whether the script protocol uses the encryption method, password, and TLS arguments depends on its implementation. See Custom HTTP Proxy with JavaScript for an example script.

TLS Certificate Fingerprints​

When skip-cert-verify=false, Loon validates the certificate's trust chain, expiration, and hostname. For a self-signed certificate, install and trust the certificate or configure a certificate fingerprint.

Generate a certificate fingerprint:

openssl x509 -noout -fingerprint -sha256 -inform pem -in your-cert.pem

Generate a public-key fingerprint:

openssl x509 -pubkey -noout -in your-cert.pem > server_pubkey.pem
openssl pkey -pubin -in server_pubkey.pem -outform DER | openssl dgst -sha256
